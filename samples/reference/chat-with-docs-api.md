# Chat with Docs API Reference

> **Type:** API reference · **Audience:** Developers integrating with Chat with Docs · **API version:** 1.0

The Chat with Docs API lets you upload PDFs to private workspaces, ask questions about them, and get answers with page-level citations. It also lets you run evaluations that score answer quality.

- **Base URL (local):** `http://localhost:8000`
- **Format:** JSON requests and responses, except where noted
- **Interactive docs:** `http://localhost:8000/docs` (auto-generated by FastAPI)
- **Source code:** [github.com/gideonswer/chat-with-docs](https://github.com/gideonswer/chat-with-docs)

## Quick start

Four requests take you from a new account to a cited answer.

```bash
# 1. Create an account and save the token
TOKEN=$(curl -s -X POST http://localhost:8000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email": "dev@example.com", "password": "a-long-password"}' \
  | python -c "import sys, json; print(json.load(sys.stdin)['access_token'])")

# 2. Create a workspace (returns its id, e.g. 1)
curl -X POST http://localhost:8000/api/workspaces \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Store policies"}'

# 3. Upload a PDF to workspace 1
curl -X POST http://localhost:8000/api/workspaces/1/documents \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@acme_policy.pdf"

# 4. Ask a question
curl -X POST http://localhost:8000/api/workspaces/1/chat \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question": "Can sale items be refunded?"}'
```

## Authentication

The API uses **JWT bearer tokens**. Get a token from [`POST /api/auth/register`](#register) or [`POST /api/auth/login`](#log-in), then send it in the `Authorization` header of every other request:

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

- Tokens expire after **24 hours** by default (`jwt_expire_minutes` setting). When a token expires, log in again.
- A missing, invalid or expired token returns `401 Unauthorized`.

### Data isolation

Every workspace belongs to one user. Requests for a workspace, document or evaluation run that belongs to another user return **`404 Not Found`**, not `403`, so the API never confirms that another user's resource exists.

## Errors

Errors return an HTTP status code and a JSON body with a `detail` field:

```json
{ "detail": "Workspace not found" }
```

For `422` validation errors, `detail` is a list describing each invalid field:

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "password"],
      "msg": "String should have at least 8 characters"
    }
  ]
}
```

| Status | Meaning | Typical cause |
|---|---|---|
| `400` | Bad request | Wrong file type; running an evaluation with no documents |
| `401` | Unauthorized | Missing, invalid or expired token; wrong login details |
| `404` | Not found | The resource doesn't exist **or belongs to another user** |
| `409` | Conflict | Email already registered |
| `413` | Payload too large | PDF larger than the upload limit (20 MB by default) |
| `422` | Unprocessable | A field fails validation, or the PDF has no extractable text |
| `503` | Service unavailable | Both the main and backup AI models failed. Retry later |

## Health

### Check service status

```http
GET /api/health
```

Returns the service status and the AI models in use. No authentication required.

#### Response `200 OK`

```json
{
  "status": "ok",
  "llm": "gemini:gemini-3.8-flash",
  "fallback": "groq:llama-3.3-70b-versatile"
}
```

`fallback` is `null` when no backup model is configured.

## Auth

### Register

```http
POST /api/auth/register
```

Creates an account and returns a token. No authentication required.

#### Request body

| Field | Type | Required | Description |
|---|---|---|---|
| `email` | string | Yes | A valid email address. Stored in lowercase. |
| `password` | string | Yes | 8–72 characters |

```json
{ "email": "dev@example.com", "password": "a-long-password" }
```

#### Response `201 Created`

```json
{ "access_token": "eyJhbGciOiJIUzI1NiIs...", "token_type": "bearer" }
```

**Errors:** `409` Email already registered · `422` Invalid email or password length

### Log in

```http
POST /api/auth/login
Content-Type: application/x-www-form-urlencoded
```

Returns a new token. This endpoint follows the OAuth2 password flow, so it takes **form fields, not JSON**, and the email goes in a field called `username`.

#### Form fields

| Field | Type | Required | Description |
|---|---|---|---|
| `username` | string | Yes | The account's email address |
| `password` | string | Yes | The account's password |

```bash
curl -X POST http://localhost:8000/api/auth/login \
  -d "username=dev@example.com" \
  -d "password=a-long-password"
```

**Response `200 OK`:** same as [Register](#register).

**Errors:** `401` Wrong email or password

### Get current user

```http
GET /api/auth/me
```

#### Response `200 OK`

```json
{ "id": 1, "email": "dev@example.com" }
```

**Errors:** `401` Invalid or expired token

## Workspaces

A **workspace** is a private collection of documents. Questions are answered only from documents in the workspace you ask in.

### Workspace object

| Field | Type | Description |
|---|---|---|
| `id` | integer | Unique ID |
| `name` | string | Display name |
| `created_at` | string (ISO 8601) | When the workspace was created |
| `document_count` | integer | Number of documents in the workspace |

### List workspaces

```http
GET /api/workspaces
```

Returns all workspaces owned by the current user.

#### Response `200 OK`

```json
[
  { "id": 1, "name": "Store policies", "created_at": "2026-11-20T10:15:02", "document_count": 1 }
]
```

### Create a workspace

```http
POST /api/workspaces
```

#### Request body

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | Yes | 1–120 characters. Leading and trailing spaces are removed. |

**Response `201 Created`:** a [workspace object](#workspace-object).

### Delete a workspace

```http
DELETE /api/workspaces/{workspace_id}
```

Permanently deletes the workspace, all its documents, their search index entries and their evaluation runs. **This can't be undone.**

#### Response `204 No Content`

**Errors:** `404` Workspace not found

## Documents

### Document object

| Field | Type | Description |
|---|---|---|
| `id` | integer | Unique ID |
| `filename` | string | Original file name |
| `num_pages` | integer | Pages in the PDF |
| `num_chunks` | integer | Searchable chunks the PDF was split into |
| `created_at` | string (ISO 8601) | Upload time |

### List documents

```http
GET /api/workspaces/{workspace_id}/documents
```

**Response `200 OK`:** an array of [document objects](#document-object).

### Upload a document

```http
POST /api/workspaces/{workspace_id}/documents
Content-Type: multipart/form-data
```

Uploads a PDF, extracts its text page by page, and indexes it for search. The request returns when indexing is complete.

#### Form fields

| Field | Type | Required | Description |
|---|---|---|---|
| `file` | file | Yes | A text-based PDF, up to 20 MB |

#### Response `201 Created`

```json
{ "id": 3, "filename": "acme_policy.pdf", "num_pages": 4, "num_chunks": 9, "created_at": "2026-11-20T10:16:40" }
```

#### Errors

| Status | `detail` | Fix |
|---|---|---|
| `400` | Only PDF files are supported | Upload a file ending in `.pdf` |
| `413` | File is larger than 20 MB | Split the PDF, or raise `MAX_UPLOAD_MB` |
| `422` | No text found. Scanned/image-only PDFs need OCR first. | Run OCR on the PDF, then upload again |
| `422` | Could not read PDF: … | The file is damaged or isn't really a PDF |

> ⏱️ The first upload after the server starts also downloads the embedding model (about 90 MB), so it can take a minute.

### Delete a document

```http
DELETE /api/workspaces/{workspace_id}/documents/{document_id}
```

Deletes the document, its stored file and its search index entries.

#### Response `204 No Content`

**Errors:** `404` Document not found

## Chat

### Ask a question

```http
POST /api/workspaces/{workspace_id}/chat
```

Searches the workspace's documents for passages relevant to the question, and returns an answer that cites them.

#### Request body

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `question` | string | Yes | | 1–2000 characters |
| `top_k` | integer | No | `5` (server setting) | Number of passages to retrieve, 1–20. Higher values help with questions that span several pages. |

```json
{ "question": "Can sale items be refunded?", "top_k": 5 }
```

#### Response `200 OK`

```json
{
  "answer": "No. Sale items can be exchanged but not refunded [1].",
  "sources": [
    {
      "ref": 1,
      "document_id": 3,
      "filename": "acme_policy.pdf",
      "page": 2,
      "text": "Sale items may be exchanged but are not eligible for a refund...",
      "score": 0.7412
    }
  ],
  "cited_refs": [1],
  "model": "gemini:gemini-3.8-flash",
  "latency_ms": 1840
}
```

| Field | Type | Description |
|---|---|---|
| `answer` | string | The answer. `[n]` markers refer to `sources[].ref`. |
| `sources` | array | **Every** passage retrieved, in ranked order, whether or not it was cited |
| `sources[].ref` | integer | The number used in `[n]` markers |
| `sources[].page` | integer | Page number in the PDF, starting from 1 |
| `sources[].score` | number | Similarity to the question; higher is more relevant |
| `cited_refs` | integer[] | The source numbers the answer actually cites. Invalid numbers are removed. |
| `model` | string | The model that wrote the answer, as `provider:model`. Shows the backup model if the main one failed. |
| `latency_ms` | integer | Total time to retrieve and answer, in milliseconds |

**When the answer isn't in the documents,** `answer` is exactly `I couldn't find that in the uploaded documents.` and `cited_refs` is empty. Compare against this string to detect it.

**Errors:** `404` Workspace not found · `503` AI model unavailable: … (both models failed; retry later)

## Evaluations

Evaluations run a set of test questions through the chat pipeline and score the results. See [How to Measure Whether Your RAG Answers Are Accurate](../how-to/measure-rag-accuracy.md) for what each metric means.

### Run an evaluation

```http
POST /api/workspaces/{workspace_id}/evals
```

Runs every test case and saves the scored results. The request returns when all cases have finished, which can take a while for large sets.

#### Request body

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `cases` | array | Yes | | 1–50 test cases |
| `cases[].question` | string | Yes | | The question to ask |
| `cases[].expected_answer` | string | Yes | | The correct answer, used for scoring |
| `cases[].expected_filename` | string \| null | No | `null` | File that should contain the answer |
| `cases[].expected_page` | integer \| null | No | `null` | Page that should contain the answer. Leave `null` for questions the documents can't answer. |
| `use_llm_judge` | boolean | No | `true` | Also have the AI model grade each answer 1–5. Uses one extra model call per case. |
| `notes` | string | No | `""` | Free text to label the run, for example the settings you're testing |

```json
{
  "cases": [
    {
      "question": "How much does express shipping cost?",
      "expected_answer": "Rs 149, and it arrives in 2 days",
      "expected_filename": "acme_policy.pdf",
      "expected_page": 3
    }
  ],
  "use_llm_judge": true,
  "notes": "baseline: chunk 900, top_k 5"
}
```

**Response `201 Created`:** an [evaluation run object](#evaluation-run-object).

**Errors:** `400` Upload at least one document before running an eval · `404` Workspace not found

### List evaluation runs

```http
GET /api/workspaces/{workspace_id}/evals
```

Returns all runs for the workspace, newest first.

### Get an evaluation run

```http
GET /api/workspaces/{workspace_id}/evals/{run_id}
```

**Errors:** `404` Eval run not found

### Evaluation run object

| Field | Type | Description |
|---|---|---|
| `id` | integer | Unique ID |
| `model` | string | Model or models that answered, comma-separated |
| `summary` | object | Aggregate scores (see below) |
| `results` | array | One object per test case, with the answer, scores and retrieved pages |
| `notes` | string | The notes you supplied |
| `created_at` | string (ISO 8601) | When the run finished |

**`summary` fields.** Rates are between 0 and 1. A value is `null` when no case could be scored for it, for example `retrieval_hit_rate` when no case has an `expected_page`.

| Field | Description |
|---|---|
| `cases` | Number of test cases |
| `errors` | Cases that failed because the model was unavailable |
| `retrieval_hit_rate` | Share of cases where the expected page was retrieved |
| `mrr` | Mean reciprocal rank of the expected page |
| `citation_hit_rate` | Share of cases where the answer cited the expected page |
| `cites_sources_rate` | Share of answers that cite at least one source |
| `refusal_rate` | Share of answers that said the information couldn't be found |
| `avg_token_f1` | Average word overlap with the expected answer |
| `avg_judge_score` | Average LLM-judge score, 1–5 |
| `judge_pass_rate` | Share of judged answers scoring 4 or higher |
| `avg_latency_ms` | Average time per answer |

<summary><strong>Writer's notes</strong>: decisions behind this piece</summary>

- **Written from the source code.** Every limit, default and error message was taken from the app's schemas and routers, not from memory, so the reference matches what the API actually does.
- **Quick start first.** Most readers of a reference want a working request before they want every field. Four `curl` calls get them from nothing to a cited answer.
- **Calls out the surprises:** login takes form data, not JSON; other users' resources return `404`, not `403`; `sources` includes uncited passages. These are the details that cost integrators an hour of debugging.
- **Errors include fixes,** not just status codes.
- **Consistent structure** for every endpoint: method and path, description, request table, example, response, errors.
